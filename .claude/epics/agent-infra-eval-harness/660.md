# Task: Code grader implementation

## Description
Implement the deterministic code grader that runs pytest-style assertions on typed `DomainAssessment` fields. This is the simplest grader type — pure functions that check direction, confidence bounds, trend_strength, iv_regime, and other typed fields against expected values from an `EvalDefinition`.

## Acceptance Criteria
- [ ] `CodeGrader` class/function that accepts `EvalDefinition` + `DomainAssessment` and returns `EvalRun`
- [ ] Assertions on: direction match, confidence range, domain-specific fields
- [ ] Pure functions — no I/O, no network calls, deterministic
- [ ] Returns structured `EvalRun` with pass/fail, details (which assertions passed/failed)
- [ ] Supports all 6 `DomainAssessment` subclasses (Trend, Volatility, Flow, Fundamental, Risk, Contrarian)

## Technical Details
- New file: `src/options_arena/evals/__init__.py` (new module)
- New file: `src/options_arena/evals/code_grader.py`
- Grader checks direction match, confidence within expected range, and custom assertions per desk type
- `details` field in EvalRun contains JSON with per-assertion pass/fail breakdown
- No I/O — this is a pure computation module

```python
    def test_direction_match_passes(self) -> None:

    def test_confidence_in_range_passes(self) -> None:
        """Verify pass when confidence within expected range."""

    def test_confidence_out_of_range_fails(self) -> None:
        """Verify fail when confidence outside range."""

    def test_trend_specific_fields(self) -> None:
        """Verify trend_strength and momentum_signal assertions."""

    def test_volatility_specific_fields(self) -> None:
        """Verify iv_regime and vol_skew assertions."""

    def test_all_six_assessment_types(self) -> None:
        """Verify grader works with all 6 DomainAssessment subclasses."""

    def test_none_fields_skipped(self) -> None:
        """Verify optional None fields don't cause assertion failures."""

    def test_details_contains_breakdown(self) -> None:
        """Verify EvalRun.details has per-assertion pass/fail JSON."""
```

### Edge Cases
- All optional fields are None — should pass (nothing to assert against)
- Confidence exactly at range boundary — should pass (inclusive)
- No expected_direction in EvalDefinition — skip direction check
- Empty custom_assertions list — only default checks run

- No mocking needed — pure function tests with constructed models
