# Task: Model Extension — Add Confidence Fields to StrategyRule

## Description
Extend `StrategyRule` model in `models/strategy.py` with 3 new fields: `confidence`, `last_validated`, and `validation_count`. These fields enable confidence decay, outcome-triggered validation, and auto-promotion/demotion of strategy rules.

## Acceptance Criteria
- [ ] `StrategyRule` has `confidence: float = 0.5` with `math.isfinite()` + `[0.0, 1.0]` validator
- [ ] `StrategyRule` has `last_validated: datetime | None = None` with UTC validator (when not None)
- [ ] `StrategyRule` has `validation_count: int = 0` with non-negative validator
- [ ] `StrategyRule` remains `frozen=True`
- [ ] Existing tests still pass (backward-compatible defaults)
- [ ] JSON round-trip preserves new fields including `None` for `last_validated`
- [ ] Re-export from `models/__init__.py` unchanged (StrategyRule already exported)

## Technical Details
- `StrategyRule` is in `src/options_arena/models/strategy.py`
- Model is `frozen=True` — immutable snapshot pattern
- Existing validators: `_validate_win_rate`, `_validate_avg_return`, `_validate_sample_size`, `_validate_utc` (for `created_at`)
- New `confidence` field reuses same pattern as `win_rate` validator (isfinite + [0.0, 1.0])
- New `last_validated` field: `datetime | None = None` — reuse UTC validator pattern from `created_at` but allow `None`
- New `validation_count` field: reuse pattern from `sample_size` validator (non-negative int)
- All new fields have defaults so existing code that creates `StrategyRule` without these fields continues to work

   - `confidence: float = 0.5`
   - `last_validated: datetime | None = None`
   - `validation_count: int = 0`
   - WHY: enables confidence decay and outcome-triggered validation tracking
2. Add `_validate_confidence` field_validator for `confidence`:
   - `math.isfinite()` check first (NaN defense pattern from CLAUDE.md)
   - Then `0.0 <= v <= 1.0` range check
   - WHY: confidence is a probability measure, same pattern as `win_rate`
3. Add `_validate_last_validated` field_validator for `last_validated`:
   - Allow `None` (never-validated rules)
   - When not None, enforce UTC (same pattern as `_validate_utc`)
   - WHY: datetime fields must enforce UTC per project rules
4. Add `_validate_validation_count` field_validator for `validation_count`:
   - `v >= 0` check
   - WHY: counts are non-negative, same pattern as `sample_size`
