# Task: Migration 038 — Confidence Columns and Repository Update

## Description
Add migration 038 to add `confidence`, `last_validated`, and `validation_count` columns to the `strategy_rules` table. Update `LearningMixin` in `data/_learning.py` to persist and retrieve these new columns, including a new `update_rule_confidence()` method for decay updates.

## Acceptance Criteria
- [ ] Migration `038_confidence_decay.sql` adds 3 columns with defaults to `strategy_rules`
- [ ] `save_strategy_rule()` persists all 3 new fields
- [ ] `get_strategy_rules()` reconstructs `StrategyRule` with all 3 new fields
- [ ] `_row_to_strategy_rule()` reads new columns from DB rows
- [ ] New method `update_rule_confidence(rule_id, confidence, last_validated, validation_count)` added
- [ ] New method `update_rule_status_and_confidence(rule_id, status, confidence)` for auto-promote/demote
- [ ] Round-trip test: save rule with confidence → read back → fields match
- [ ] Migration is idempotent with existing data (defaults fill for existing rows)

## Technical Details
- Migration file: `data/migrations/038_confidence_decay.sql`
- Repository mixin: `src/options_arena/data/_learning.py` (LearningMixin)
- Current `save_strategy_rule()` inserts 8 columns — extend to 11
- Current `_row_to_strategy_rule()` reconstructs from Row — add 3 new column reads
- `last_validated` stored as ISO 8601 TEXT (nullable), reconstructed via `datetime.fromisoformat()`
- aiosqlite pattern: `await conn.commit()` after every write

### Action
1. Create `data/migrations/038_confidence_decay.sql` with 3 ALTER TABLE statements:
   - `ALTER TABLE strategy_rules ADD COLUMN confidence REAL DEFAULT 0.5;`
   - `ALTER TABLE strategy_rules ADD COLUMN last_validated TEXT;`
   - `ALTER TABLE strategy_rules ADD COLUMN validation_count INTEGER DEFAULT 0;`
   - WHY: extends strategy_rules schema for confidence decay tracking
2. Update `save_strategy_rule()` in `_learning.py` to include 3 new columns in INSERT:
   - Add `confidence`, `last_validated` (as ISO string or None), `validation_count`
   - WHY: persist new StrategyRule fields
3. Update `_row_to_strategy_rule()` to read 3 new columns:
   - `confidence=float(row["confidence"])` (with fallback to 0.5 for NULL)
   - `last_validated` — parse ISO string or None
   - `validation_count=int(row["validation_count"])` (with fallback to 0)
   - WHY: reconstruct full StrategyRule from DB
4. Add `update_rule_confidence()` method to LearningMixin:
   - Parameters: `rule_id: str, confidence: float, last_validated: datetime | None, validation_count: int`
   - SQL: `UPDATE strategy_rules SET confidence=?, last_validated=?, validation_count=? WHERE rule_id=?`
   - Returns `bool` (True if row updated)
   - WHY: decay logic needs to update confidence without replacing entire rule
5. Add `update_rule_status_and_confidence()` method:
   - Parameters: `rule_id: str, status: RuleStatus, confidence: float`
   - SQL: `UPDATE strategy_rules SET status=?, confidence=? WHERE rule_id=?`
   - Returns `bool`
   - WHY: auto-promote/demote needs atomic status + confidence update
