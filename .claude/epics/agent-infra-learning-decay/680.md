# Task: Decay Logic — confidence_decay.py Core Functions

## Description
Create `learning/confidence_decay.py` with 4 functions: `decay_confidence()` (pure math), `validate_rules_against_outcomes()` (cross-reference conditions vs P&L), `auto_promote_demote()` (threshold-based status changes), and `run_confidence_decay()` (orchestration wrapper). These implement the confidence decay pipeline that runs when outcomes are collected.

## Acceptance Criteria
- [ ] `decay_confidence(rule, now)` returns decayed confidence using exponential decay (5% per month)
- [ ] Never-validated rules get 50% penalty applied to decayed confidence
- [ ] `validate_rules_against_outcomes(rules, outcomes)` cross-references rule conditions against outcome data and returns updated rules
- [ ] `auto_promote_demote(rules, repo)` promotes rules with confidence >= 0.8 AND validation_count >= 5, demotes rules with confidence < 0.3
- [ ] `run_confidence_decay(repo)` orchestrates the full pipeline, never-raises
- [ ] All pure functions have no I/O; orchestration wrapper handles DB access
- [ ] Module follows `learning/` architecture: imports from `models/`, `data/` only

## Technical Details
- New file: `src/options_arena/learning/confidence_decay.py`
- Decay formula: `confidence * (0.95 ** months_since_validation)` where months = days / 30.44
- Never-validated penalty: if `last_validated is None` and `validation_count == 0`, apply `* 0.5`
- Auto-promote threshold: `confidence >= 0.8 AND validation_count >= 5` → status = APPROVED
- Auto-demote threshold: `decayed confidence < 0.3` → status = REJECTED
- Only CANDIDATE rules are eligible for auto-promotion; only CANDIDATE and APPROVED for demotion
- `run_confidence_decay()` follows never-raises contract (catch, log, return empty)
- Uses `Repository.update_rule_confidence()` and `Repository.update_rule_status_and_confidence()` from Task 002

2. Implement `decay_confidence(rule: StrategyRule, now: datetime) -> float`:
   - Pure function, no I/O
   - If `rule.last_validated is None`: months_since = days since `rule.created_at`
   - Else: months_since = days since `rule.last_validated`
   - `months = (now - reference_date).total_seconds() / (30.44 * 86400)`
   - `decayed = rule.confidence * (0.95 ** months)`
   - If never validated (`rule.last_validated is None and rule.validation_count == 0`): `decayed *= 0.5`
   - Return `max(0.0, min(1.0, decayed))` — clamp to [0.0, 1.0]
   - WHY: exponential decay with never-validated penalty, clamped for safety
3. Implement `validate_rules_against_outcomes(rules, outcomes) -> list[tuple[str, bool]]`:
   - Pure function: for each rule, check if outcome data supports its conditions
   - Returns list of (rule_id, is_validated) tuples
   - A rule is validated if outcomes matching its conditions have win_rate >= rule.win_rate * 0.8
   - WHY: cross-reference mined patterns against actual recent outcomes
4. Implement `auto_promote_demote(rules: list[StrategyRule]) -> tuple[list[str], list[str]]`:
   - Pure function returning (promote_ids, demote_ids)
   - Promote: CANDIDATE rules with confidence >= 0.8 AND validation_count >= 5
   - Demote: CANDIDATE or APPROVED rules with confidence < 0.3
   - WHY: threshold-based automated rule lifecycle management
5. Implement `run_confidence_decay(repo: Repository) -> None`:
   - Async orchestration wrapper with never-raises contract
   - Fetch all non-rejected rules, apply decay, validate against recent outcomes
   - Persist updated confidence values and status changes
   - WHY: top-level entry point called from outcomes collection flow
