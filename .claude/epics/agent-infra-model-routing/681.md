# Task: Complexity Assessment and Model Routing Logic

## Description
Implement `agents/model_routing.py` with complexity assessment heuristics and tier routing logic. The `_assess_complexity()` function scores a ticker's analysis difficulty from MarketContext + TickerScore fields. `route_model_tier()` maps complexity to a `ModelTier`. `build_model_for_tier()` constructs the appropriate PydanticAI model for the selected tier.

## Acceptance Criteria
- [ ] `_assess_complexity(context, ticker_score)` returns float in [0.0, 1.0]
- [ ] Complexity considers: completeness_ratio, earnings proximity, conflicting indicators, extreme IV, low liquidity
- [ ] `route_model_tier(desk, context, ticker_score, config)` returns correct `ModelTier` for all thresholds
- [ ] Risk desk always returns STANDARD or PREMIUM (never FAST)
- [ ] Synthesis always returns PREMIUM
- [ ] `build_model_for_tier(tier, config)` returns correct PydanticAI Model
- [ ] When `enable_model_routing` is False, all desks use STANDARD tier
- [ ] All functions have full type annotations

## Technical Details
- New file: `src/options_arena/agents/model_routing.py`
- `_assess_complexity()` is a pure function (no I/O, no side effects)
- Complexity heuristics (each contributes a weighted score):
  - `completeness_ratio < 0.6` → +0.2 (missing data = harder)
  - Earnings within 7 days → +0.2 (catalyst event)
  - RSI > 80 or < 20 → +0.1 (extreme readings)
  - IV rank > 80 → +0.15 (extreme volatility)
  - Put/call ratio > 2.0 or < 0.3 → +0.1 (unusual flow)
  - ADX < 15 → +0.1 (no clear trend = harder)
  - Composite score < 30 or > 85 → +0.15 (extreme scores = ambiguous)
- Sum is clamped to [0.0, 1.0]
- `build_model_for_tier()` dispatches to `build_debate_model()` with config overrides per tier

### Action
1. Create `src/options_arena/agents/model_routing.py` with module docstring
   - WHY: new file for routing logic, separate from model_config.py (which handles provider construction)
2. Implement `_assess_complexity(context: MarketContext, ticker_score: TickerScore) -> float`:
   - Initialize `score = 0.0`
   - Check `context.completeness_ratio()` if available, else skip
   - Check earnings proximity: `context.next_earnings` within 7 days of today
   - Check RSI extremes from `ticker_score.signals.rsi`
   - Check IV rank from `ticker_score.signals.iv_rank`
   - Check put/call ratio from `ticker_score.signals.put_call_ratio`
   - Check ADX from `ticker_score.signals.adx`
   - Check composite score extremes from `ticker_score.composite_score`
   - Guard every `float | None` field with `is not None and math.isfinite()` before comparison
   - Clamp result to `[0.0, 1.0]` via `min(1.0, max(0.0, score))`
   - WHY: NaN defense on all optional indicator fields
3. Implement `route_model_tier(desk: DeskType, context: MarketContext, ticker_score: TickerScore, config: RoutingConfig) -> ModelTier`:
   - If `not config.enable_model_routing`, return `ModelTier.STANDARD`
   - If `desk == DeskType.RISK`, return `max(ModelTier.STANDARD, complexity_tier)`
   - Compute complexity via `_assess_complexity(context, ticker_score)`
   - If complexity < `config.complexity_threshold_fast` → `ModelTier.FAST`
   - If complexity >= `config.complexity_threshold_premium` → `ModelTier.PREMIUM`
   - Else → `ModelTier.STANDARD`
   - WHY: risk desk safety rule + opt-in routing
4. Implement `build_model_for_tier(tier: ModelTier, config: DebateConfig) -> Model`:
   - `ModelTier.FAST` → override `config.model` with `config.routing.fast_model`, call `build_debate_model()`
   - `ModelTier.STANDARD` → call `build_debate_model(config)` unchanged
   - `ModelTier.PREMIUM` → if `config.routing.premium_model`, use it; else use default model
   - WHY: reuses existing model construction, only overrides the model name per tier
5. Add re-exports in `src/options_arena/agents/__init__.py`:
   - `route_model_tier`, `build_model_for_tier` (public), `_assess_complexity` stays private
   - WHY: standard re-export pattern
