# Task: CLI Cost Summary and API Cost Analytics Endpoint

## Description
Add `--cost-summary` flag to the `debate` CLI command to display per-desk cost breakdown after a recommendation runs. Add `GET /api/analytics/recommendation-costs` REST endpoint for cost trend analytics over time.

## Acceptance Criteria
- [ ] `options-arena debate AAPL --cost-summary` shows per-desk breakdown table
- [ ] Cost table shows: desk name, model tier, model name, tokens, estimated cost
- [ ] `--cost-summary` without routing enabled shows a note that routing is disabled
- [ ] `GET /api/analytics/recommendation-costs` returns cost summaries from recent recommendations
- [ ] API endpoint filters by optional `?ticker=` and `?limit=` query params
- [ ] CLI cost table uses Rich formatting (Table with colored tier badges)
- [ ] No cost display when no recommendation was run (e.g., debate-only mode)

## Technical Details
- CLI: modify `src/options_arena/cli/debate.py` to accept `--cost-summary` flag
- CLI: add `_render_cost_summary(result: RecommendationResult)` function
- API: add endpoint in `src/options_arena/api/routes/analytics.py`
- API response model: `CostSummaryResponse` with list of per-recommendation cost data
- DB query: `RecommendationMixin` already has `get_recommendation()` — extend or add `get_recommendation_costs()` to query desk_metrics stored in JSON column
- Cost data is already on `RecommendationResult` from task 003 — just need display + persistence query

### Action
1. In `src/options_arena/cli/debate.py`, add `--cost-summary` flag to debate command:
   - `cost_summary: bool = typer.Option(False, "--cost-summary", help="Show per-desk cost breakdown")`
   - WHY: opt-in flag, no change to default behavior
2. In `src/options_arena/cli/debate.py`, add `_render_cost_summary()` function:
   - Takes `RecommendationResult` as input
   - Creates `rich.table.Table` with columns: Desk, Tier, Model, Tokens (In), Tokens (Out), Est. Cost
   - Color-code tier column: FAST=green, STANDARD=yellow, PREMIUM=red
   - Show total row at bottom
   - If `result.cost is None`, print note: "Model routing disabled — no cost data available"
   - WHY: Rich table follows existing CLI patterns for scan/debate output
3. Call `_render_cost_summary()` after debate/recommendation completes when flag is set:
   - Guard: only call if result has recommendation data (not debate-only mode)
   - WHY: cost data only exists on RecommendationResult
4. In `src/options_arena/api/routes/analytics.py`, add cost analytics endpoint:
   - `GET /api/analytics/recommendation-costs`
   - Query params: `ticker: str | None = None`, `limit: int = 20`
   - Returns list of cost summaries from recent recommendations
   - WHY: enables frontend/API consumers to track cost trends
5. Add response model for cost endpoint:
   - `CostAnalyticsItem` with: `ticker`, `created_at`, `total_tokens`, `total_cost_usd`, `tier_distribution`, `desk_count`
   - `CostAnalyticsResponse` with `items: list[CostAnalyticsItem]`
   - WHY: typed response model per project rules (no raw dicts)
6. In `src/options_arena/data/_recommendation.py`, add query method:
   - `get_recommendation_costs(ticker: str | None, limit: int) -> list[CostAnalyticsItem]`
   - Query `recommendation_results` table, parse `desk_metrics` JSON, aggregate
   - WHY: persistence layer provides data for the API endpoint
