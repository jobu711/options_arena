# Epic: agent-infra-tool-response

## Overview

Wrap all desk agent tools in `_toolsets.py` with a structured `ToolResponse` model that
includes status, summary, and recovery guidance. When a tool fails or returns partial
data, the agent gets explicit `next_actions` telling it how to adjust its assessment —
rather than guessing. This replaces the current raw string returns with structured JSON
while keeping the `str` return type signature.

## Scope Boundary

### In Scope
- `ToolResponse[T]` generic Pydantic model with status, summary, data, next_actions
- `ToolStatus` StrEnum (SUCCESS, WARNING, ERROR)
- Refactor all 23 tool functions in `agents/_toolsets.py` to return `ToolResponse` JSON
- Update 7 desk recommendation prompts to reference ToolResponse format
- Tests: verify each tool returns valid ToolResponse JSON on success and error paths

### Out of Scope (handled by sibling epics)
- Eval framework (agent-infra-eval-harness)
- Per-desk model routing (agent-infra-model-routing)
- Strategy rule confidence decay (agent-infra-learning-decay)

## Architecture Decisions

- **Option A (str return)**: Tools keep returning `str` via `model_dump_json()` — zero change to PydanticAI tool signatures, consistent with existing codebase convention
- `ToolResponse` is generic (`Generic[T]`) for typed payloads but serialized to JSON string
- `next_actions` are hand-crafted per tool failure mode — not generated by LLM
- Existing never-raises contract preserved — ToolResponse wraps both success and error cases
- `ToolStatus.WARNING` for partial data (e.g., some indicators available but not all)

## Technical Approach

### Data Model (`models/tool_response.py`)
- `ToolStatus` StrEnum: SUCCESS, WARNING, ERROR
- `ToolResponse[T]` frozen model: status, summary (one-line), data (T | None), next_actions (list[str])

### Tool Refactoring (`agents/_toolsets.py`)
Each of the 23 tool functions refactored from:
```python
async def tool_name(ctx, ticker) -> str:
    try:
        data = await ...
        return f"Result: {data}"
    except Exception:
        return f"Error: ..."
```
To:
```python
async def tool_name(ctx, ticker) -> str:
    try:
        data = await ...
        return ToolResponse(
            status=ToolStatus.SUCCESS,
            summary=f"{ticker}: ...",
            data=data,
            next_actions=["assess X", "compare Y"],
        ).model_dump_json()
    except Exception as exc:
        return ToolResponse(
            status=ToolStatus.ERROR,
            summary=f"Unavailable: {_sanitize(exc)}",
            data=None,
            next_actions=["set field to None", "reduce confidence", "note data gap"],
        ).model_dump_json()
```

### Prompt Updates (`agents/prompts/recommend_*.py`)
Add a section to each of the 7 recommendation desk prompts explaining the ToolResponse
format and how to interpret status/next_actions.
