# Task: Conditional Registration in Toolset Builders

## Description
Wire the 4 new ML/statistical tool wrappers into their target desk toolset builders using conditional registration for optional-dep tools (`compute_garch_forecast_tool`, `compute_markov_regime_tool`) and direct registration for always-available tools (`compute_macro_regime_tool`, `compute_hurst_exponent_tool`). Add `render_available_tools()` function that generates `<<<AVAILABLE_TOOLS>>>` prompt blocks from registered toolsets.

## Acceptance Criteria
- [ ] `build_trend_toolset()` includes `compute_hurst_exponent_tool` (always) + `compute_markov_regime_tool` (conditional)
- [ ] `build_volatility_toolset()` includes `compute_garch_forecast_tool` (conditional)
- [ ] `build_fundamental_toolset()` includes `compute_macro_regime_tool` (always)
- [ ] `build_risk_toolset()` includes `compute_macro_regime_tool` (always) + `compute_markov_regime_tool` (conditional)
- [ ] `build_research_toolset()` includes all 4 tools (2 always + 2 conditional)
- [ ] Conditional tools use `try/except ImportError` on the underlying indicator module (not on the tool wrapper itself)
- [ ] Toolsets build successfully when `[ml]` extra IS installed
- [ ] Toolsets build successfully when `[ml]` extra is NOT installed (conditional tools omitted)
- [ ] `render_available_tools()` produces correct `<<<AVAILABLE_TOOLS>>>` block
- [ ] Existing `test_toolset_registration.py` tool counts updated to reflect new tools
- [ ] Type annotations pass `mypy --strict`

## Technical Details
- Conditional import pattern: test if the underlying indicator module is importable by importing the source function (not the tool wrapper). The tool wrapper does its own lazy import, but we need to verify the dep is available before registering the tool.
- For GARCH: `try: from options_arena.indicators.vol_forecast import compute_garch_forecast; tools.append(compute_garch_forecast_tool)` — note: `compute_garch_forecast` itself does `_get_arch()` which returns None if `arch` missing, BUT the import itself may fail if `arch` isn't installed since `vol_forecast.py` unconditionally has `import pandas as pd` etc. Check: does `import options_arena.indicators.vol_forecast` succeed without `arch`? YES — `vol_forecast.py` uses guarded `_get_arch()` function, not top-level import. So we need a different guard.
- Actually, CORRECT approach: since `vol_forecast.py` uses `_get_arch()` (lazy), the module itself IS importable without `arch`. The tool wrapper calls `compute_garch_forecast` which calls `_get_arch()` and returns None if missing. So the tool handles ImportError gracefully already. We could just always register. BUT the epic says to use conditional registration (tool omitted, not no-op). So we should directly try `import arch` (the actual dep).
- For Markov: `try: import statsmodels` or `try: from statsmodels.tsa.regime_switching.markov_regression import MarkovRegression`
- `render_available_tools(toolset: list[object]) -> str` — new function in `_toolsets.py`
- Update existing test file `test_toolset_registration.py` tool counts
