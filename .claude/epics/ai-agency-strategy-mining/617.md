# Task: API endpoints, CLI commands, and LearningDashboard playbook tab

## Description
Expose strategy mining and playbook management through all three interfaces: REST API endpoints, CLI subcommands, and a Vue 3 frontend tab on the LearningDashboard page. The API provides `POST /api/learning/mine` to trigger mining, `GET /api/learning/playbook` to list rules, and `PUT /api/learning/playbook/{id}` to approve/reject rules. CLI adds `learn mine` and `learn playbook` subcommands. Frontend adds a Playbook tab to the existing learning dashboard with approve/reject buttons.

## Acceptance Criteria
- [ ] `POST /api/learning/mine` triggers mining and returns generated rules
- [ ] `GET /api/learning/playbook` returns list of strategy rules (filterable by status)
- [ ] `PUT /api/learning/playbook/{id}` updates rule status (approve/reject)
- [ ] CLI `learn mine` triggers mining with progress output
- [ ] CLI `learn playbook` lists rules with status, win rate, sample size
- [ ] Operation mutex respected: mining requires lock (409 if busy)
- [ ] LearningDashboard.vue has a Playbook tab showing strategy rules
- [ ] Approve/reject buttons on each rule row in the Playbook tab
- [ ] Rate limiting on all new endpoints

   ```python
   @limiter.limit("30/minute")
   async def update_rule(
       request: Request,
       rule_id: str,
       status: RuleStatus = Query(...),
       repo: Repository = Depends(get_repo),
   ) -> dict[str, bool]:
       updated = await repo.update_rule_status(rule_id, status)
       if not updated:
           raise HTTPException(404, f"Rule not found: {rule_id}")
       return {"updated": True}
   ```

### Edge Cases
- Mining with 0 outcomes: returns empty list, no error
- Mining with exactly 100 outcomes: proceeds (boundary case)
- Approving already-approved rule: idempotent success
- Invalid status value in PUT: 422 validation error
- Empty playbook: GET returns empty list, CLI prints "No rules found"
- Concurrent mine requests: second request gets 409

### Mocking Strategy
- API tests: mock `Repository` via FastAPI dependency override
- CLI tests: mock `asyncio.run` target or use `CliRunner` with mocked services
- Frontend: no backend tests — E2E tests cover this (existing Playwright setup)
