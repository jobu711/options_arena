# Task: Implement indicator weight tuning via outcome P&L correlation

## Description
Add `compute_indicator_tune_weights()` to `learning/weight_tuner.py`. This function correlates historical indicator signals (from `IndicatorSignals` on `TickerScore`) with outcome P&L to produce optimized indicator weights. The algorithm uses Pearson correlation of each indicator's percentile-rank value with subsequent contract P&L, then normalizes to sum=1.0 with floor/cap clamping.

## Acceptance Criteria
- [ ] `compute_indicator_tune_weights()` exists in `learning/weight_tuner.py`
- [ ] Takes list of `(IndicatorSignals, float)` tuples (signals + P&L return)
- [ ] Returns `dict[str, float]` mapping indicator field name to weight (sum=1.0)
- [ ] Floor clamp: no indicator weight below 0.01
- [ ] Cap clamp: no indicator weight above 0.15
- [ ] Indicators with <10 non-None values retain their static weight from `INDICATOR_WEIGHTS`
- [ ] `WeightType` StrEnum added to `models/enums.py`
- [ ] `WeightSnapshot` extended with `weight_type` and `accuracy_at_time` fields
- [ ] Function is pure — no I/O, no DB calls
- [ ] Never-raises contract: returns static weights on any error

## Technical Details
- Algorithm: For each indicator field, compute Pearson r between percentile-rank values and P&L returns. Convert |r| to raw weight, clamp [0.01, 0.15], normalize to sum=1.0.
- Import `INDICATOR_WEIGHTS` from `scoring.composite` for static fallback.
- `WeightType` enum: `VOTE = "vote"`, `INDICATOR = "indicator"`.
- `WeightSnapshot.weight_type` defaults to `WeightType.VOTE` for backward compat.
