# Task: Eval data models and enums

## Description
Create the foundational Pydantic models and StrEnum types for the eval harness. These define the shape of eval definitions, eval runs, and eval reports. All other eval tasks depend on these models.

## Acceptance Criteria
- [ ] `EvalType` StrEnum with CAPABILITY and REGRESSION members
- [ ] `GraderType` StrEnum with CODE, MODEL, OUTCOME members
- [ ] `EvalVerdict` StrEnum with SHIP, NEEDS_WORK, BLOCKED members
- [ ] `EvalDefinition` frozen model with all fields from epic spec
- [ ] `EvalRun` frozen model with all fields and validators
- [ ] `EvalReport` frozen model with pass@k metrics and verdict
- [ ] All confidence/float fields have `math.isfinite()` + range validators
- [ ] All datetime fields have UTC validators
- [ ] JSON round-trip tests pass for all 3 models
- [ ] Re-exported from `models/__init__.py`

## Technical Details
- New file: `src/options_arena/models/eval.py`
- Add enums to `src/options_arena/models/enums.py`
- Follow existing model patterns: `ConfigDict(frozen=True)`, field validators
- `EvalDefinition.expected_confidence_range` as `tuple[float, float] | None`
- `EvalDefinition.target_desk` as `DeskType | None` (None = synthesis agent)
- `EvalRun.duration_ms` as `int` with non-negative validator
- `EvalReport.pass_at_1` and `pass_at_3` as `float` with [0.0, 1.0] + isfinite validators
