# Task: Outcome grader implementation (P&L calibration)

## Description
Implement the outcome-based grader that compares `PositionRecommendation.direction` and `confidence` against actual P&L from historical outcome data. This grader checks calibration: recommendations with 70% confidence should be correct ~70% of the time. It queries persisted outcomes from the database.

## Acceptance Criteria
- [ ] `OutcomeGrader` compares direction + confidence against actual P&L
- [ ] Calibration check: high confidence should correlate with win rate
- [ ] Queries outcomes from Repository (EvalMixin or AnalyticsMixin)
- [ ] Returns `EvalRun` with calibration metrics in details
- [ ] Handles insufficient outcome data gracefully (skip with warning)
- [ ] Pure logic after data fetch — calibration math is deterministic

## Technical Details
- New file: `src/options_arena/evals/outcome_grader.py`
- Needs access to Repository for outcome queries (via parameter injection, not global)
- Calibration logic: group recommendations by confidence bucket (0.5-0.6, 0.6-0.7, etc.), compare predicted win rate vs actual
- Pass criteria: actual win rate within ±15% of predicted confidence for each bucket
- Minimum samples per bucket: 5 (skip bucket if insufficient)

### Action
1. Create `src/options_arena/evals/outcome_grader.py` with `run_outcome_grader()` function
   - WHY: calibration-based grading needs historical outcome data
2. Implement confidence bucketing: group by confidence ranges [0.5-0.6), [0.6-0.7), [0.7-0.8), [0.8-1.0]
   - WHY: calibration measured per confidence bucket, not overall
3. Compare predicted win rate (bucket midpoint) vs actual win rate per bucket
   - WHY: well-calibrated model has predicted ≈ actual
4. Pass if all buckets with sufficient samples (≥5) are within ±15% tolerance
   - WHY: reasonable tolerance for stochastic financial data
5. Return `EvalRun` with calibration table in details JSON
   - WHY: debugging and reporting need per-bucket breakdown
6. Handle insufficient data: return EvalRun with passed=False, details explaining data shortage
   - WHY: graceful degradation, never-raises

### Edge Cases
- All outcomes in same confidence bucket — only that bucket evaluated
- All outcomes are wins — passes if confidence is high
- Zero outcomes — returns failed with "insufficient data" details
- Confidence exactly at bucket boundary — assigned to lower bucket
