# Task: Eval runner with pass@k and baseline comparison

## Description
Build the eval orchestrator that loads eval definitions, dispatches to the appropriate grader, runs multiple attempts for pass@k computation, compares results against baselines, and produces an `EvalReport` with SHIP/NEEDS_WORK/BLOCKED verdict. This is the central coordination layer of the eval harness.

## Acceptance Criteria
- [ ] `run_eval_suite()` loads definitions, dispatches to graders, returns `EvalReport`
- [ ] pass@1: fraction of evals passing on first attempt
- [ ] pass@3: fraction of evals passing at least once in 3 attempts
- [ ] Baseline comparison: load stored baseline, detect regressions
- [ ] Verdict logic: SHIP if pass@1 >= threshold and no regressions; NEEDS_WORK if regressions; BLOCKED if pass@1 < min_threshold
- [ ] Persists eval runs to SQLite via EvalMixin
- [ ] Supports filtering by desk type (`--desk`)
- [ ] Never-raises orchestration (catches grader failures, continues suite)

## Technical Details
- New file: `src/options_arena/evals/runner.py`
- Loads eval definitions from `.claude/evals/*.json` (git-tracked)
- Dispatches based on `grader_type`: CODE → code_grader, MODEL → model_grader, OUTCOME → outcome_grader
- For pass@k: runs each eval `k` times (configurable via `EvalConfig.pass_at_k`)
- Baseline stored as JSON in `.claude/evals/baseline.json` — previous pass rates per eval
- Regression = eval that passed in baseline but fails now
- Verdict thresholds configurable via `EvalConfig`
