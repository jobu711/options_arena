# Task: Orchestrator Integration — Per-Desk Routing and Metrics

## Description
Wire the model routing, metrics accumulation, and assessment summary into `recommendation_orchestrator.py`. Before each desk agent runs, select the appropriate model tier based on complexity. Measure per-desk timing and token usage, accumulate into `DeskMetrics` list. After all desks complete, compute `AssessmentSummary` (direction votes, avg confidence, disagreement desks, risk flags, data completeness) from the 6 `DomainAssessment` results and inject it into the synthesis prompt. Compute `RecommendationCost` and attach all three to `RecommendationResult`.

## Acceptance Criteria
- [ ] Each desk agent receives a model selected by `route_model_tier()` when routing is enabled
- [ ] When routing is disabled, behavior is identical to current (single model for all desks)
- [ ] `DeskMetrics` captured for every desk (success and fallback)
- [ ] `RecommendationCost` computed after synthesis phase
- [ ] `AssessmentSummary` computed from 6 DomainAssessments between Phase 1 and Phase 2
- [ ] `AssessmentSummary` injected into synthesis prompt (populates `agent_agreement_score` and `dissenting_desks`)
- [ ] `RecommendationResult` includes populated `desk_metrics`, `assessment_summary`, and `cost` fields
- [ ] Fallback results still include `desk_metrics` (with status="fallback") and `assessment_summary=None`
- [ ] No change to the public `run_recommendation()` signature
- [ ] Synthesis agent always uses PREMIUM tier (or STANDARD when routing disabled)

## Technical Details
- Modify `_run_desk()` inner function in `recommendation_orchestrator.py`
- Add `time.monotonic()` measurement around each desk runner call
- Extract `RunUsage` from desk results (if available via `result.usage()`)
- Token usage comes from `DomainAssessment.model_used` and the runner's `RunUsage`
- For fallback assessments, `DeskMetrics` has `status="fallback"`, `duration_ms` from wall clock, zero tokens
- `RecommendationCost.total_cost_usd` = sum of (tokens / 1_000_000) * cost_per_million_tokens per model
- Cost estimation uses `config.routing.cost_per_million_tokens` lookup by model name
- If model name not in pricing map, cost is 0.0 (free tier / unknown)

### Action
1. In `recommendation_orchestrator.py`, import routing functions:
   - `from options_arena.agents.model_routing import build_model_for_tier, route_model_tier`
   - `from options_arena.models import DeskMetrics, ModelTier, RecommendationCost, RoutingConfig`
   - WHY: wire routing into the pipeline
2. Modify `_run_recommendation_pipeline()` to compute per-desk model tiers:
   - After building `desk_deps`, compute tier for each desk via `route_model_tier()`
   - Store `desk_tier_map: dict[DeskType, ModelTier]` for lookup
   - WHY: tier selection must happen before the parallel gather
3. Modify `_run_desk()` inner function:
   - Accept `tier: ModelTier` parameter
   - Build per-desk model via `build_model_for_tier(tier, config)` when routing enabled
   - Wrap runner call with `time.monotonic()` measurement
   - Return `(DomainAssessment, DeskMetrics)` tuple instead of bare `DomainAssessment`
   - On fallback: `DeskMetrics(status="fallback", duration_ms=..., model_tier=tier, ...)`
   - WHY: captures timing and model selection per desk
4. After `asyncio.gather()`, separate assessments and metrics:
   - Unzip the tuple list into `assessments` and `desk_metrics`
   - WHY: clean data flow into RecommendationResult
5. Compute `AssessmentSummary` from 6 DomainAssessments:
   - Count direction votes (`direction_votes: dict[SignalDirection, int]`)
   - Average confidence across all assessments (`avg_confidence: float`)
   - Identify desks disagreeing with majority direction (`disagreement_desks: list[DeskType]`)
   - Extract risk flags from `RiskDeskAssessment` (look for `risks` or `key_factors` fields)
   - Compute `data_completeness` as fraction of non-None assessment fields across all 6
   - WHY: structured consensus/disagreement data for synthesis agent — directly supports `agent_agreement_score` and `dissenting_desks` on `PositionRecommendation`
6. Inject `AssessmentSummary` into synthesis deps or prompt:
   - Add `assessment_summary` field to `SynthesisDeps` and pass computed summary
   - Update synthesis prompt dynamic section to render the summary as structured context
   - WHY: synthesis agent needs consensus data to weigh assessments and set agreement score
7. For synthesis, use PREMIUM tier if routing enabled:
   - `synth_tier = ModelTier.PREMIUM if config.routing.enable_model_routing else ModelTier.STANDARD`
   - Build synthesis model via `build_model_for_tier(synth_tier, config)`
   - Measure synthesis timing and create a `DeskMetrics` entry for synthesis
   - WHY: synthesis is the final recommendation — warrants best model
8. After synthesis, compute `RecommendationCost`:
   - Sum all `DeskMetrics` token counts
   - Look up cost per model in `config.routing.cost_per_million_tokens`
   - Build `tier_distribution` counter
   - WHY: cost estimation for observability
9. Construct `RecommendationResult` with all observability data:
   - Pass `desk_metrics=all_metrics`, `assessment_summary=summary`, and `cost=cost`
   - WHY: attach observability data to the result
10. Update `_build_fallback_recommendation_result()` to include empty metrics:
   - `desk_metrics=[]`, `assessment_summary=None`, `cost=None`
   - WHY: fallback results should have consistent shape

### Edge Cases
- All 6 desks fail → 6 fallback DeskMetrics + 1 synthesis fallback, assessment_summary=None
- All 6 desks agree on direction → disagreement_desks is empty, avg_confidence is high
- 3-3 split on direction → disagreement_desks has 3 entries, avg_confidence likely moderate
- Routing enabled but all tickers resolve to STANDARD (thresholds never crossed)
- `cost_per_million_tokens` map is empty (all costs = 0.0)
- Token counts are 0 (TestModel produces no real tokens)
