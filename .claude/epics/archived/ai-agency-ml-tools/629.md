# Task: Integration Tests — Toolset Degradation and End-to-End

## Description
Create comprehensive tests that verify: (1) all 7 desk toolset builders produce valid toolsets with and without `[ml]` extra, (2) each new tool wrapper integrates correctly with mocked services and indicator functions, (3) desk agents can successfully invoke ML tools via TestModel, and (4) `render_available_tools()` accurately reflects registered tools in all configurations.

## Acceptance Criteria
- [ ] Tests verify all 7 desks build valid toolsets with `[ml]` installed
- [ ] Tests verify all 7 desks build valid toolsets without `[ml]` (graceful degradation)
- [ ] Tests verify tool count changes between with/without `[ml]` configurations
- [ ] Tests verify GARCH tool end-to-end with mocked OHLCV + mocked indicator
- [ ] Tests verify Markov tool end-to-end with mocked OHLCV + mocked indicator
- [ ] Tests verify Macro tool end-to-end with mocked FRED service
- [ ] Tests verify Hurst tool end-to-end with mocked OHLCV
- [ ] Tests verify `render_available_tools()` output matches registered tools per desk
- [ ] All tests use mocks — no real API calls, no real ML model fitting
- [ ] Tests marked with `@pytest.mark.critical` for happy-path coverage

## Technical Details
- Use `monkeypatch` to simulate missing `arch` / `statsmodels` packages
- For end-to-end: create full `DeskDeps` with mocked services, call tool functions directly with mock `RunContext`
- Verify that conditional tool counts are deterministic: with `[ml]` each desk has N tools, without it has N-k tools
- Expected tool counts (with [ml]): volatility=5, trend=5, fundamental=5, risk=8, research=13, flow=3, contrarian=2
- Expected tool counts (without [ml]): volatility=4, trend=4, fundamental=5, risk=7, research=11, flow=3, contrarian=2
- The contrarian and flow desks are unaffected by ML tools
