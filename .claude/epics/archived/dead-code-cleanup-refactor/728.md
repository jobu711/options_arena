# Task: Extract _check_api_provider in health.py

## Description
Extract a shared `_check_api_provider()` helper method from `check_groq()` (lines 117-208)
and `check_anthropic()` (lines 210-304) in `services/health.py`. Both methods share ~80
lines of identical status-code branching, timer logic, and exception handling.

## Acceptance Criteria
- [ ] New `_check_api_provider()` private method extracted in `HealthService`
- [ ] `check_groq()` and `check_anthropic()` refactored to call the shared helper
- [ ] Identical behavior preserved (same HealthStatus returns for all cases)
- [ ] ~80 lines of duplication eliminated
- [ ] Existing health tests still pass
- [ ] New tests for the extracted helper

## Technical Details

### Duplicated pattern in both methods:
1. `start = time.monotonic()`
2. Resolve API key: `config.groq_api_key` or env var → if None, return unavailable
3. `async with self._client.get(url, headers=headers, timeout=timeout)` (or similar)
4. Status code branching: 401 → invalid key, 403 → forbidden, 429 → rate limited, 500+ → server error, else → healthy
5. Each branch builds `HealthStatus(name=..., available=..., latency_ms=..., details=...)`
6. Exception handler: catch `Exception`, return unavailable with error message

### Proposed helper signature:
```python
async def _check_api_provider(
    self,
    *,
    name: str,
    url: str,
    headers: dict[str, str],
    timeout: float,
) -> HealthStatus:
    """Check an API provider endpoint with standard status-code handling."""
```

### Unique per-provider logic to keep outside helper:
- API key resolution (different config fields, different env vars)
- Key-not-found early return (different warning messages)
- Provider-specific URL and header construction
