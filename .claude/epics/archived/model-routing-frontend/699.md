# Task: Orchestrator token attribution and always-compute cost

## Description
Update `recommendation_orchestrator.py` to: (1) update `_DeskRunner` protocol to expect `tuple[DomainAssessment, RunUsage]`, (2) extract `RunUsage` from desk runner results and populate `DeskMetrics.input_tokens`/`output_tokens`, (3) aggregate per-desk usage into `RecommendationResult.total_usage`, and (4) always compute cost (remove `enable_model_routing` gate).

## Acceptance Criteria
- [ ] `_DeskRunner` protocol return type is `tuple[DomainAssessment, RunUsage]`
- [ ] `_run_desk()` extracts `RunUsage` from desk runner and populates `DeskMetrics.input_tokens`/`output_tokens`
- [ ] Fallback/exception paths in `_run_desk()` use `RunUsage()` (empty)
- [ ] `RecommendationResult.total_usage` aggregated from per-desk `RunUsage`
- [ ] `_compute_recommendation_cost()` always called (gate removed)
- [ ] `RecommendationResult.cost` is always populated (never `None`)
- [ ] Existing orchestrator tests still pass

## Technical Details
- `_DeskRunner` is a `Protocol` class defining the desk runner callable signature
- `_run_desk()` calls the desk runner, constructs `DeskMetrics`, returns `tuple[DomainAssessment, DeskMetrics]`
- Currently `DeskMetrics` at line 571 doesn't set `input_tokens`/`output_tokens` (defaults to 0)
- Currently `total_usage=RunUsage()` at line 672 is always empty
- Currently `_compute_recommendation_cost()` gated on `routing_config.enable_model_routing` at line 660

Files affected:
- `src/options_arena/agents/recommendation_orchestrator.py`

### Action
1. Update `_DeskRunner` Protocol return type from `DomainAssessment` to `tuple[DomainAssessment, RunUsage]`
   - WHY: desk runners now return usage data alongside assessment (Task 697)
2. In `_run_desk()` success path (line ~564-578): extract usage from runner result
   - `assessment, usage = await runner(...)` instead of `assessment = await runner(...)`
   - Add `input_tokens=usage.input_tokens, output_tokens=usage.output_tokens` to `DeskMetrics` constructor
   - WHY: populate DeskMetrics with real token counts
3. In `_run_desk()` exception path (line ~579-590): use empty RunUsage
   - `DeskMetrics(..., input_tokens=0, output_tokens=0)` (already default, but explicit)
   - WHY: failed desk calls have no token usage
4. In the BaseException handler (line ~599-610): same — zero tokens for fallback
   - WHY: gather exceptions produce no tokens
5. Aggregate total_usage (line ~672): replace `RunUsage()` with aggregated usage
   - `total_in = sum(m.input_tokens for m in desk_metrics)`
   - `total_out = sum(m.output_tokens for m in desk_metrics)`
   - `total_usage = RunUsage(input_tokens=total_in, output_tokens=total_out)`
   - WHY: RecommendationResult.total_usage should reflect actual token usage
6. Remove `enable_model_routing` gate on `_compute_recommendation_cost()` (line ~660-663)
   - Change from `if routing_config.enable_model_routing` to always call
   - WHY: cost is meaningful even with default model (map has entry for llama-3.3-70b-versatile)
7. Update the `cost` variable: always assigned from `_compute_recommendation_cost()`, never `None`
