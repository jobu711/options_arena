# Task: Orchestrator prediction persistence

## Description

Hook prediction recording into `recommendation_orchestrator.py`. After desk agents
return assessments and synthesis completes, create `Prediction` objects for each desk +
synthesis and persist them. Also persist scan predictions (from `ScoringResult`) with the
real `scan_run_id` and `recommendation_id`. All recording is never-raises.

## Acceptance Criteria

- [ ] One `Prediction` per desk agent persisted after desk execution
- [ ] One `Prediction` for synthesis persisted after synthesis completes
- [ ] Scan predictions from `ScoringResult.scan_predictions` persisted with real `scan_run_id`
- [ ] Context snapshot from `MarketContext` (adx, iv_rank, atr_pct, rsi) on desk predictions
- [ ] All persistence via `repo.save_predictions_batch()`
- [ ] Never-raises: recording failures logged, recommendation pipeline continues
- [ ] Fallback assessments recorded with their (low) confidence
- [ ] Unit tests pass

## Technical Details

- Hook location: `_persist_recommendation()` method (~line 705-735), after `save_recommendation()` returns `rec_id`
- `DeskMetrics` carries `desk: DeskType`, assessment has `direction` and `confidence`
- `MarketContext` has `adx`, `iv_rank`, `atr_pct`, `rsi` for context snapshot
- Map `DeskType` → `PredictionSource`: e.g., `DeskType.TREND` → `PredictionSource.DESK_TREND`
- `scan_run_id` available in `_persist_recommendation()` as parameter
- Scan predictions have `scan_run_id=0` placeholder — replace before persisting

### Action
1. Add helper `_desk_type_to_prediction_source(desk: DeskType) -> PredictionSource`:
   - Map `DeskType.TREND → PredictionSource.DESK_TREND`, etc. for all 6 desks
   - Skip `DeskType.RESEARCH` (not a prediction source)
   - WHY: clean mapping between desk enum and prediction source enum
2. Add helper `_build_desk_predictions(desk_results, rec_id, ticker, market_context) -> list[Prediction]`:
   - Iterate desk results, create `Prediction` per desk with:
     - `recommendation_id=rec_id`, `ticker=ticker`
     - `source` from desk type mapping
     - `predicted_direction` and `confidence` from assessment
     - Context from `MarketContext` (adx, iv_rank, atr_pct, rsi)
   - Skip desks that don't have assessments (failed desks)
   - WHY: isolates prediction building from persistence logic
3. In `_persist_recommendation()`, after `save_recommendation()` returns `rec_id`:
   ```python
   try:
       predictions = _build_desk_predictions(desk_results, rec_id, ticker, context)
       # Add synthesis prediction
       predictions.append(Prediction(
           recommendation_id=rec_id, ticker=ticker,
           source=PredictionSource.SYNTHESIS,
           predicted_direction=recommendation.direction, ...
       ))
       # Add scan predictions with real scan_run_id
       for sp in scoring_result.scan_predictions:
           predictions.append(sp.model_copy(update={"scan_run_id": scan_run_id}))
       await repo.save_predictions_batch(predictions)
   except Exception:
       logger.warning("Failed to persist predictions for rec %d", rec_id)
   ```
   - WHY: never-raises, batch persist for atomicity, after save_recommendation ensures rec_id exists
4. Pass `scoring_result` through to `_persist_recommendation()` if not already accessible:
   - WHY: needed to access `scan_predictions` collected during Phase 2
