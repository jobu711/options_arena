# Task: Data layer — score and query prediction methods

## Description

Add `score_predictions()`, `score_scan_predictions()`, `get_predictions()`, and
`get_prediction_accuracy()` methods to `LearningMixin`. These complete the CRUD layer:
scoring marks predictions correct/incorrect after outcome collection, and query methods
power the attribution report.

## Acceptance Criteria

- [ ] `score_predictions(recommendation_id: int, was_correct: bool, *, commit: bool = True) -> int` — UPDATE all predictions for a recommendation, return count updated
- [ ] `score_scan_predictions(scan_run_id: int, ticker: str, was_correct: bool, *, commit: bool = True) -> int` — UPDATE scan predictions, return count
- [ ] `get_predictions(window_days: int, source: PredictionSource | None = None) -> list[Prediction]` — query scored and unscored predictions
- [ ] `get_prediction_accuracy(window_days: int) -> list[PredictionAccuracy]` — grouped accuracy stats
- [ ] Scoring is idempotent (re-scoring same prediction overwrites)
- [ ] `get_prediction_accuracy` respects window_days filter
- [ ] Private helper `_row_to_prediction(row: Row) -> Prediction` added

## Technical Details

- `score_predictions()`: `UPDATE predictions SET was_correct = ? WHERE recommendation_id = ?`
- `score_scan_predictions()`: `UPDATE predictions SET was_correct = ? WHERE scan_run_id = ? AND ticker = ?`
- Both return `cursor.rowcount` (number of rows affected)
- `get_predictions()`: SELECT with `WHERE created_at >= ?` (window filter), optional `AND source = ?`
- `get_prediction_accuracy()`: SQL aggregation `GROUP BY source` with `COUNT(*)`, `SUM(was_correct)`, `WHERE was_correct IS NOT NULL`
- `_row_to_prediction()` follows `_row_to_strategy_rule()` pattern — reconstruct Pydantic from Row

### Action
1. Add `_row_to_prediction(row: Row) -> Prediction` static method to `LearningMixin`:
   - Reconstruct `PredictionSource` from `row["source"]`, `SignalDirection` from `row["predicted_direction"]`
   - Parse `created_at` from ISO string with UTC fallback (same pattern as `_row_to_strategy_rule`)
   - Map `row["was_correct"]` → `bool | None`: NULL → None, 0 → False, 1 → True
   - WHY: follows existing Row-to-model reconstruction pattern
2. Add `score_predictions()` method:
   - UPDATE with parameterized query, `was_correct` mapped to int (0/1)
   - Return `cursor.rowcount`
   - WHY: batch update all desk + synthesis predictions for a recommendation after outcome collection
3. Add `score_scan_predictions()` method:
   - UPDATE matching `scan_run_id` AND `ticker`
   - WHY: scan predictions link via (scan_run_id, ticker), not recommendation_id
4. Add `get_predictions()` method:
   - Build SQL with `created_at >= datetime.now(UTC) - timedelta(days=window_days)`
   - Optional `source` filter added dynamically
   - Return `[_row_to_prediction(row) for row in rows]`
   - WHY: flexible query for attribution analysis with time window
5. Add `get_prediction_accuracy()` method:
   - SQL: `SELECT source, COUNT(*) as total, SUM(was_correct) as correct FROM predictions WHERE was_correct IS NOT NULL AND created_at >= ? GROUP BY source`
   - Compute `accuracy = correct / total`, `sample_sufficient = total >= 10`
   - Return `list[PredictionAccuracy]`
   - WHY: pre-aggregated accuracy stats, avoids loading all predictions into memory

- Single source with 0 correct out of N → accuracy = 0.0
