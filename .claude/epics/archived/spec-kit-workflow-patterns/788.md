## Technical Details

### Architecture Decision (from research)

`depends_on` is the single source of truth. Both `parallel: true` frontmatter and `[P]`
markdown markers are derived views:

| Signal | Location | Consumer | Purpose |
|--------|----------|----------|---------|
| `depends_on: [N]` | Task frontmatter | `epic-start` | **Source of truth** — execution ordering |
| `parallel: true` | Task frontmatter | `epic-sync`, `epic-status` | Derived — PM command statistics |
| `[P]` | Task list markdown | `parallel-worker`, humans | Derived — visual scanning + agent fan-out |

### Convention Rules

- `[P]` means "this task can execute concurrently with other `[P]` tasks in the same phase"
- Tasks without `[P]` are sequential barriers — all preceding `[P]` tasks must complete first
- Phase boundaries are always sequential barriers
- `(depends on T{X}.{Y})` annotations optional but recommended
- A task gets `[P]` iff its `depends_on` entries all resolve to earlier phases (or empty)
