# Task: Triage & Fix P1 Findings

## Description
Review the consolidated audit report from Task 567, fix all P1 findings using `/fix-loop`, and document unfixed P2 findings as known limitations. This is the critical-path task — effort depends entirely on P1 count.

## Acceptance Criteria
- [ ] All P1 findings from audit report resolved
- [ ] Each fix verified with targeted tests (lint, type check, relevant test file)
- [ ] P2 findings documented in `docs/known-limitations-v2.10.0.md`
- [ ] No regressions introduced by fixes (full test suite still passes)
- [ ] `/compound` run for any novel solutions discovered during fixing

## Technical Details
- P1 findings may include: security vulnerabilities, incorrect formulas, critical bugs, high CVEs, architecture boundary violations
- `/fix-loop` runs iterative audit-fix-verify cycles with user approval between iterations (max 3 iterations)
- If fixes touch logic, targeted tests must be added (per PRD testing strategy)
- If math audit found formula errors, fixes must be verified against cited papers
- Known research concern: `position_sizing.py` documented as "Kelly criterion" but implements vol-regime-tier heuristic — if flagged as P1, update documentation rather than reimplementing

## Execution

### Read First
Files that MUST be read before starting this task:
- `.claude/audits/v2-release-audit.md` — consolidated findings from Task 567
- `.claude/epics/v2-release-prep/research.md` — known concerns and context

### Action
1. Read `.claude/audits/v2-release-audit.md` and list all P1 findings
   - WHY: Need to know exact scope before starting fixes
2. For each P1 finding, run `/fix-loop` with the specific finding as input
   - WHY: Iterative fix-verify cycle ensures each fix is correct before moving on
3. After each fix, run targeted verification:
   - `uv run ruff check <modified_files> --fix && uv run ruff format <modified_files>`
   - `uv run mypy <modified_files> --strict`
   - `uv run pytest <relevant_test_file> -v`
   - WHY: Catch regressions immediately, before they compound
4. If any fix introduces a novel pattern or solution, run `/compound` to capture it
   - WHY: Self-improvement loop — prevents repeating same discoveries
5. After all P1s fixed, run full test suite: `uv run pytest -m "not exhaustive" -n auto -q`
   - WHY: Ensure no regressions across the codebase
6. Document remaining P2 findings in `docs/known-limitations-v2.10.0.md`
   - WHY: Transparency — users and future developers know what was deferred
7. Commit all fixes: `fix: resolve P1 audit findings for v2.10.0 release`
   - WHY: Atomic commit grouping all P1 fixes together
