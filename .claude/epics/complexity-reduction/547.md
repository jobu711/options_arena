# Task: Delete OpenBB models, service, slim config, and clean MarketContext

## Description

Wave 2 (moderate risk). Delete the entire OpenBB enrichment service and its models. Slim `OpenBBConfig` to CBOE-only fields. Remove 12 OpenBB-sourced fields from `MarketContext`. Remove `SentimentLabel` enum. Clean re-exports and health check. Delete dedicated OpenBB test files.

## Acceptance Criteria

- [ ] `services/openbb_service.py` deleted
- [ ] `models/openbb.py` deleted
- [ ] `OpenBBConfig` slimmed to 5 CBOE-only fields: `cboe_chains_enabled`, `chains_cache_ttl`, `chain_validation_mode`, `request_timeout`, `max_retries`
- [ ] 12 OpenBB-sourced fields removed from `MarketContext` (pe_ratio, forward_pe, peg_ratio, price_to_book, debt_to_equity, revenue_growth, profit_margin, net_call_premium, net_put_premium, options_put_call_ratio, news_sentiment, recent_headlines) + `news_sentiment_label`
- [ ] `enrichment_ratio()` adjusted to exclude removed fields
- [ ] `SentimentLabel` StrEnum deleted from `enums.py`
- [ ] `OpenBBService` removed from `services/__init__.py`
- [ ] OpenBB model re-exports removed from `models/__init__.py`
- [ ] `check_openbb()` removed from `services/health.py`
- [ ] 3 dedicated OpenBB test files deleted
- [ ] Tests constructing `MarketContext` or `OpenBBConfig` with removed fields updated
- [ ] `ruff check` + `mypy --strict` pass

## Technical Details

- `OpenBBConfig` is kept (not renamed per PRD) but slimmed from 12 fields to 5 CBOE-only fields. The CBOE chain provider is architecturally independent.
- `MarketContext` has both OpenBB-sourced fields and FinancialDatasets `fd_*` fields. Only OpenBB fields are removed; FD fields remain.
- `enrichment_ratio()` counts populated enrichment fields. After removal, it should only count remaining FD fields.
- `SentimentLabel` is only used by OpenBB models — safe to delete entirely.
- The health check `check_openbb()` is a separate method in `HealthService` — remove the method and its call in `check_all()`.
