# Task: Clean integration points — orchestrator, API, CLI, agent parsing

## Description

Wave 3 (highest risk due to breadth). Remove all OpenBB references from the integration layer: orchestrator (`build_market_context()`, `run_debate()`), agent parsing (`_parsing.py` rendering sections), API (app lifespan, deps, debate routes, schemas), and CLI (commands, `--no-openbb` flag). Delete remaining OpenBB test files.

## Acceptance Criteria

- [ ] `build_market_context()` no longer accepts `fundamentals`/`flow`/`sentiment` params
- [ ] `run_debate()` no longer passes OpenBB data to `build_market_context()`
- [ ] 3 OpenBB rendering sections removed from `agents/_parsing.py`
- [ ] OpenBB service removed from `api/app.py` lifespan
- [ ] `get_openbb()` removed from `api/deps.py`
- [ ] OpenBB fetch/pass-through removed from `api/routes/debate.py`
- [ ] `news_sentiment_label` field removed from `api/schemas.py`
- [ ] OpenBB import, service creation, and `--no-openbb` flag removed from `cli/commands.py`
- [ ] 6 dedicated OpenBB test files deleted
- [ ] ~10 additional test files with OpenBB references updated
- [ ] `ruff check` + `mypy --strict` pass on all modified files

## Technical Details

- `build_market_context()` in `orchestrator.py` currently has a complex waterfall: OpenBB fields → FD fields → None. After this change, FD fields map directly without waterfall logic.
- `_parsing.py` has 3 OpenBB-specific rendering sections (Fundamental Profile, Unusual Options Flow, News Sentiment). The FD-sourced fundamental rendering (separate section) remains.
- The API lifespan creates `OpenBBService` and stores it on `app.state.openbb`. This is removed along with the `get_openbb()` dependency provider.
- CLI `--no-openbb` flag is a breaking change for scripts. Typer will error on unknown flags.
- `api/schemas.py` imports `SentimentLabel` (now deleted) for a response field.
