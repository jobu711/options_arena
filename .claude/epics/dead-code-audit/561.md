# Task: Wire hurst_exponent into Phase 2

## Description

Connect the existing `hurst_exponent()` indicator function to the scan pipeline. The function, model field, DOMAIN_BOUNDS entry, and composite weight (0.01) all exist. Only the computation call in `scan/indicators.py` is missing.

## Acceptance Criteria

- [ ] `hurst_exponent()` called during Phase 2 indicator computation
- [ ] Result mapped to `IndicatorSignals.hurst_exponent` field
- [ ] Non-finite results guarded with `math.isfinite()`
- [ ] Integration test verifies field is populated with valid close series
- [ ] Composite score changes by up to 0.01 (weight was silently redistributed before)

## Technical Details

### Why not INDICATOR_REGISTRY?
`hurst_exponent()` returns `float | None`, but `INDICATOR_REGISTRY` expects functions returning `pd.Series` (the registry takes `result.iloc[-1]` as scalar). The correct wiring pattern is `_compute_ohlcv_dse()` (lines 282-310 in `scan/indicators.py`) which handles scalar indicators directly.

### Existing infrastructure
- **Function**: `hurst_exponent(close: pd.Series, min_bars=200, max_lag=100, r_squared_threshold=0.5) -> float | None` in `indicators/hurst.py`
- **Field**: `IndicatorSignals.hurst_exponent: float | None = None` (already exists)
- **Domain bounds**: `"hurst_exponent": (0.0, 1.0)` in `scoring/normalization.py` (line 74)
- **Weight**: `"hurst_exponent": (0.01, "regime")` in `scoring/composite.py` (line 65)
- **Wiring gap**: Not imported or called in `scan/indicators.py`

### Implementation pattern
Follow the same pattern as `compute_dollar_volume_trend` and `compute_volume_profile_skew` in `_compute_ohlcv_dse()` (lines 296-310):
```python
try:
    hurst = hurst_exponent(close_series)
    if hurst is not None and math.isfinite(hurst):
        signals.hurst_exponent = hurst
except Exception:
    logger.warning("hurst_exponent failed; setting to None", exc_info=True)
```
