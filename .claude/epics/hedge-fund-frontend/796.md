# Task: Test suite — component, store, and integration tests

## Description

Set up Vitest for the web project (if not already configured), then write comprehensive tests for the pipeline store, all new components, and key integration flows. This is the final quality gate before the epic is complete.

## Acceptance Criteria

- [ ] Vitest configured and running in `web/` project
- [ ] Pipeline store tests cover full state machine (idle → scanning → scanned → analyzing → ready/failed)
- [ ] Component tests for all 9 new components (DeskCard, PipelineStatus, ScanProgressCard, ScanControlBar, OpportunityTable, DeskAssessmentCard, AgentConsensus, PositionCard, AttributionPanel)
- [ ] All tests pass with `npx vitest run`
- [ ] Minimum 50 test cases across all test files
- [ ] Edge cases covered: null fields, empty arrays, partial data, 0 results

## Technical Details

### Vitest setup (if not present)
```bash
cd web && npm install -D vitest @vue/test-utils jsdom @pinia/testing
```

Add to `vite.config.ts`:
```typescript
test: {
  environment: 'jsdom',
  globals: true,
  setupFiles: ['./src/__tests__/setup.ts'],
}
```

Create `web/src/__tests__/setup.ts`:
```typescript
import { config } from '@vue/test-utils'
import { createTestingPinia } from '@pinia/testing'
// Global plugins for all tests
```

Add script to `package.json`:
```json
"test": "vitest run",
"test:watch": "vitest"
```

### Test priority (most critical first)
1. **Pipeline store** — state machine is the backbone; incorrect transitions break everything
2. **OpportunityTable** — most complex component, sort/filter/select behavior
3. **PositionCard** — price formatting correctness is a hard requirement
4. **DeskAssessmentCard** — must handle all 6 desk types and partial data
5. **AgentConsensus** — partial desks (3-4 of 6) is a known edge case
6. **DeskCard** — collapse/expand is used everywhere
7. **PipelineStatus** — 5-state correctness
8. **ScanControlBar** — button state management
9. **ScanProgressCard** — timer behavior
10. **AttributionPanel** — data fetching and rendering

### Key test patterns
```typescript
// Store tests with Pinia testing
import { setActivePinia, createPinia } from 'pinia'
import { usePipelineStore } from '@/stores/pipeline'

beforeEach(() => {
  setActivePinia(createPinia())
})

// Component tests with stubs
import { mount } from '@vue/test-utils'
const wrapper = mount(ComponentName, {
  props: { ... },
  global: {
    stubs: { DeskCard: true, DirectionBadge: true },
    plugins: [createTestingPinia()],
  }
})
```

### Edge Cases (cross-cutting)
- Null/undefined fields everywhere → `--` fallback
- Empty arrays (no tickers, no findings, no assessments)
- Partial data (3-4 desks out of 6)
- Price string formatting (never parseFloat)
- Store state machine invalid transitions (ignored gracefully)

### Mocking Strategy
- `vi.mock('@/composables/useApi')` for API-dependent components
- `createTestingPinia()` for store-dependent components
- `vi.useFakeTimers()` for ScanProgressCard elapsed time
- Stub child components (`DeskCard: true`) to isolate unit tests
