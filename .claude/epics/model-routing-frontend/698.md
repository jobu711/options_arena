# Task: API routes — config routing overlay + expanded cost endpoint

## Description
Add PUT and DELETE handlers to `routes/config.py` for the routing overlay. Expand `GET /api/config` to include routing state. Expand the recommendation costs endpoint to return per-desk breakdowns. Initialize `app.state.routing_override` in `lifespan()`. Add `get_routing_override()` dependency provider. Resolve overlay in debate route before calling `run_recommendation()`.

## Acceptance Criteria
- [ ] `PUT /api/config/routing` validates input, constructs `RoutingConfig`, stores on `app.state.routing_override`
- [ ] `DELETE /api/config/routing` clears overlay, returns base config
- [ ] `GET /api/config` includes `routing: RoutingConfigResponse` with `is_override` flag
- [ ] `GET /api/analytics/recommendation-costs` returns `desk_details` from stored `desk_metrics_json`
- [ ] `app.state.routing_override` initialized to `None` in `lifespan()`
- [ ] `get_routing_override()` dependency provider added to `deps.py`
- [ ] Debate route resolves overlay via `model_copy(update={"routing": override})`
- [ ] Rate limiting: 10/min on PUT and DELETE

## Technical Details
- PUT constructs a `RoutingConfig` from `RoutingConfigUpdate` to leverage existing model validation
- `model_copy(update=...)` does NOT validate — PUT endpoint validates before storing
- Debate route uses `get_settings()` + `get_routing_override()` to resolve config
- Cost endpoint deserializes `desk_metrics_json` from `RecommendationRow`, maps to `DeskCostDetail`

Files affected:
- `src/options_arena/api/app.py` (add `routing_override` to `app.state`)
- `src/options_arena/api/deps.py` (add `get_routing_override()`)
- `src/options_arena/api/routes/config.py` (add PUT, DELETE, expand GET)
- `src/options_arena/api/routes/analytics.py` (expand cost endpoint)
- `src/options_arena/api/routes/debate.py` (resolve overlay)

### Action
1. In `app.py` `lifespan()`, add `app.state.routing_override = None` after existing state initialization
   - WHY: initialize overlay as None (no override)
2. In `deps.py`, add `get_routing_override()` provider:
   ```python
   def get_routing_override(request: Request) -> RoutingConfig | None:
       return cast(RoutingConfig | None, request.app.state.routing_override)
   ```
   - WHY: typed DI for overlay access
3. In `routes/config.py`, add PUT handler:
   - Validate `RoutingConfigUpdate` body (FastAPI does this automatically)
   - Construct `RoutingConfig` from the update fields
   - Store on `request.app.state.routing_override`
   - Return `RoutingConfigResponse(is_override=True, ...fields...)`
   - WHY: runtime config override
4. In `routes/config.py`, add DELETE handler:
   - Set `request.app.state.routing_override = None`
   - Return `RoutingConfigResponse(is_override=False, ...base_config_fields...)`
   - WHY: reset to defaults
5. Expand GET handler to include `routing: RoutingConfigResponse` in response
   - Resolve: overlay if set, else `settings.debate.routing`
   - WHY: frontend needs current routing state
6. In `routes/analytics.py` cost endpoint, deserialize `desk_metrics_json` from `RecommendationRow`:
   - `desk_details = json.loads(row.desk_metrics_json)` if present, else `[]`
   - Map to `DeskCostDetail` objects
   - WHY: per-desk breakdown for cost table
7. In `routes/debate.py`, resolve overlay before `run_recommendation()`:
   ```python
   override = request.app.state.routing_override
   config = settings.debate.model_copy(update={"routing": override}) if override else settings.debate
   ```
   - WHY: next recommendation uses runtime override
