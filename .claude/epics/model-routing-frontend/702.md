# Task: Migration 040 + desk metrics persistence

## Description
Add `desk_metrics_json TEXT` column to `recommendation_results` table via migration 040. Update `save_recommendation()` to serialize `desk_metrics` list as JSON. Update `RecommendationRow` dataclass and `_row_to_recommendation_row()` to include the new column.

## Acceptance Criteria
- [ ] Migration 040 creates `desk_metrics_json` column with `DEFAULT '[]'`
- [ ] `save_recommendation()` serializes `desk_metrics` via `model_dump(mode="json")`
- [ ] `RecommendationRow` has `desk_metrics_json: str` field
- [ ] `_row_to_recommendation_row()` maps the new column
- [ ] Round-trip test: save → read → deserialize → matching DeskMetrics
- [ ] Pre-existing rows (NULL default) handled gracefully

## Technical Details
- Follow existing pattern: `assessments_json` uses `json.dumps([a.model_dump(mode="json") for a in ...])` — same pattern for desk_metrics
- `RecommendationRow` is a `@dataclass` (not Pydantic) — add field at end to match column order
- Migration uses `ALTER TABLE ... ADD COLUMN` pattern (30+ precedents in codebase)
- Column default `'[]'` means pre-migration rows get empty array, not NULL

Files affected:
- `data/migrations/040_desk_metrics_json.sql` (new)
- `src/options_arena/data/_recommendation.py`
