# Task: Prediction scoring functions

## Description

Create `learning/prediction_ledger.py` — the core computation module for the prediction
ledger. This task adds the scoring functions that determine whether predictions were
correct based on stock return direction. Follows the never-raises orchestration pattern.

## Acceptance Criteria

- [ ] `learning/prediction_ledger.py` created as new module
- [ ] `score_predictions_for_recommendation(repo, recommendation_id) -> int` — scores all desk + synthesis predictions
- [ ] `score_predictions_for_scan(repo, scan_run_id) -> int` — scores scan direction predictions
- [ ] `run_prediction_scoring(repo) -> None` — top-level never-raises orchestration wrapper
- [ ] Correctness based on stock return direction (positive = bullish correct)
- [ ] Never-raises: all functions catch exceptions and log
- [ ] Unit tests for scoring logic pass

## Technical Details

- **Correctness rule**: `stock_return_pct > 0` means bullish was correct, `< 0` means bearish correct, `== 0` → incorrect for all
- **Scoring by recommendation_id**: Join `predictions` → `recommendation_results` → `recommended_contracts` → `contract_outcomes` to get `stock_return_pct`
- **Scoring by scan_run_id**: Join `predictions(scan_run_id, ticker)` → `recommended_contracts(scan_run_id, ticker)` → `contract_outcomes`
- **Batch scoring**: Score all unscored predictions for recently-collected outcomes, not individual ones
- Use `repo.score_predictions()` and `repo.score_scan_predictions()` from foundation epic

### Action
1. Create `src/options_arena/learning/prediction_ledger.py` with module docstring and logger
   - WHY: new module owned by this epic, keeps scoring/attribution separate from strategy mining
2. Add helper `_direction_was_correct(predicted: SignalDirection, stock_return_pct: float) -> bool`:
   - BULLISH + positive return → True
   - BEARISH + negative return → True
   - NEUTRAL → always False (neutral predictions can't be "correct")
   - `stock_return_pct == 0.0` → False for all directions
   - WHY: isolates direction accuracy from contract selection quality per architecture decision
3. Add `async def score_predictions_for_recommendation(repo: Repository, recommendation_id: int) -> int`:
   - Query outcomes for the recommendation via `repo.get_contract_outcomes(recommendation_id)`
   - Determine overall stock direction from outcomes
   - Call `repo.score_predictions(recommendation_id, was_correct)` for each direction match
   - Return count of scored predictions
   - WHY: batch scoring after outcome collection
4. Add `async def score_predictions_for_scan(repo: Repository, scan_run_id: int) -> int`:
   - Query outcomes linked to this scan run
   - Group by ticker, determine per-ticker stock direction
   - Call `repo.score_scan_predictions(scan_run_id, ticker, was_correct)` per ticker
   - Return total count scored
   - WHY: scan predictions link via (scan_run_id, ticker)
5. Add `async def run_prediction_scoring(repo: Repository) -> None`:
   - Outer never-raises wrapper: try/except with `logger.exception()`
   - Find recently collected outcomes with unscored predictions
   - Call scoring functions for each
   - WHY: follows existing `run_confidence_decay()` pattern — called after outcome collection
