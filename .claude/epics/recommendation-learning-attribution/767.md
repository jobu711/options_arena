# Task: Scan pipeline prediction recording

## Description

Collect scan direction predictions in memory during Phase 2 scoring. Since `phase_scoring.py`
does not have `repo` access, predictions are built from `TickerScore` + `IndicatorSignals`
and attached to `ScoringResult` for the orchestrator to persist in Phase 4.

## Acceptance Criteria

- [ ] `ScoringResult` extended with `scan_predictions: list[Prediction]` field (default empty list)
- [ ] After `determine_direction()`, a `Prediction` is created per ticker with `source=SCAN_DIRECTION`
- [ ] Context snapshot populated from `raw_signals`: `adx`, `iv_rank`, `atr_pct`, `rsi`
- [ ] `scan_run_id` left as placeholder (0) — orchestrator sets actual value before persistence
- [ ] Never-raises: prediction creation failures logged and skipped, scoring continues
- [ ] No `repo` access added to `phase_scoring.py`
- [ ] Unit tests pass

## Technical Details

- `run_scoring_phase()` returns `ScoringResult` — add `scan_predictions` field to this model
- `ScoringResult` is defined in `models/scan.py` (frozen model)
- After `determine_direction()` sets `ts.direction` at line ~137, create a `Prediction`:
  - `scan_run_id=0` (placeholder — orchestrator replaces with real ID)
  - `ticker=ts.ticker`
  - `source=PredictionSource.SCAN_DIRECTION`
  - `predicted_direction=ts.direction`
  - `confidence=ts.direction_confidence`
  - Context from `raw_signals[ts.ticker]`: `adx`, `iv_rank` (may be None in Phase 2), `atr_pct`, `rsi`
- Note: `iv_rank` is likely None in Phase 2 (options data not yet fetched) — this is expected

### Edge Cases
- `raw_signals` missing for a ticker → prediction created with all context None
- Zero tickers scored → empty `scan_predictions` list
- `direction_confidence` is 0.0 → valid prediction (fallback confidence)
- Very large number of tickers (100+) → all get predictions
