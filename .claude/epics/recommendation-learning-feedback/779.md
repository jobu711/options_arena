# Task: Extend OutcomeWithContext with condition dimensions

## Description

Add ADX, ATR%, and RSI context fields to `OutcomeWithContext` in `strategy_book.py`, add
classifier functions for ADX and ATR% (matching existing `_classify_iv()` pattern), and
update the SQL query in `_fetch_outcomes_with_context()` to LEFT JOIN indicator context
from the `predictions` table. Backward-compatible: new fields default to `None`.

## Acceptance Criteria

- [ ] `OutcomeWithContext` extended with `adx: float | None = None`, `atr_pct: float | None = None`, `rsi: float | None = None`
- [ ] `ADX_BUCKETS` and `ATR_PCT_BUCKETS` constant tuples added
- [ ] `_classify_adx(adx: float | None) -> str | None` function added
- [ ] `_classify_atr_pct(atr_pct: float | None) -> str | None` function added
- [ ] `_fetch_outcomes_with_context()` SQL updated with LEFT JOIN to `predictions` table
- [ ] Existing callers of `OutcomeWithContext` unaffected (default None values)
- [ ] All existing strategy mining tests still pass
- [ ] Unit tests for new classifiers pass

## Technical Details

- `OutcomeWithContext` is a `BaseModel` (not dataclass) at lines 61-86
- Existing classifiers: `_classify_iv()` (lines 121-126), `_classify_dte()` (lines 129-134)
- Existing buckets: `IV_BUCKETS` (lines 36-42), `DTE_BUCKETS` (lines 44-48)
- SQL query at lines 478-528 joins `contract_outcomes` → `recommended_contracts` → `ticker_metadata`
- New JOIN: LEFT JOIN `predictions` ON `(rc.recommendation_id = p.recommendation_id AND p.source = 'synthesis')` to get context snapshot
- Fallback: if prediction doesn't exist for a recommendation, adx/atr_pct/rsi stay None
