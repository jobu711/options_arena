# Task: Predictions table migration

## Description

Create SQL migration `041_predictions.sql` that adds the `predictions` table with dual
FK constraints, UNIQUE constraints for idempotent recording, and 5 indexes for query
performance. Verify the migration runs on a fresh database and doesn't affect existing data.

## Acceptance Criteria

- [ ] `data/migrations/041_predictions.sql` file created
- [ ] `predictions` table with all 13 columns per PRD schema
- [ ] FK to `recommendation_results(id)` and `scan_runs(id)`
- [ ] `UNIQUE(recommendation_id, source)` constraint
- [ ] `UNIQUE(scan_run_id, ticker, source)` constraint
- [ ] 5 indexes created (source, was_correct, rec_id, scan_id, ticker)
- [ ] Migration test passes against in-memory SQLite
- [ ] Existing data unaffected (migration only adds new table)

## Technical Details

- Follow existing migration numbering: `040_desk_metrics_json.sql` → `041_predictions.sql`
- Use `CREATE TABLE IF NOT EXISTS` for safety
- Use `CREATE INDEX IF NOT EXISTS` for idempotent re-runs
- Partial indexes for `was_correct`, `recommendation_id`, `scan_run_id` (WHERE ... IS NOT NULL)
- `was_correct` is INTEGER (SQLite has no boolean): NULL=unscored, 0=incorrect, 1=correct
- `created_at` stored as TEXT (ISO format, consistent with all other tables)

## Execution

### Read First
- `data/migrations/040_desk_metrics_json.sql` — latest migration, understand format
- `data/migrations/037_learning_infrastructure.sql` — `recommendation_results` table schema (FK target)
- `src/options_arena/data/database.py` — migration runner pattern (understand how migrations execute)

### Action
1. Create `data/migrations/041_predictions.sql` with `CREATE TABLE IF NOT EXISTS predictions`
   - WHY: new table for prediction ledger, dual FK to existing tables
2. Define 13 columns matching PRD schema:
   - `id INTEGER PRIMARY KEY AUTOINCREMENT`
   - `recommendation_id INTEGER REFERENCES recommendation_results(id)` (nullable)
   - `scan_run_id INTEGER REFERENCES scan_runs(id)` (nullable)
   - `ticker TEXT NOT NULL`
   - `source TEXT NOT NULL` (PredictionSource StrEnum value)
   - `predicted_direction TEXT NOT NULL` (SignalDirection value)
   - `confidence REAL NOT NULL`
   - `adx REAL`, `iv_rank REAL`, `atr_pct REAL`, `rsi REAL` (all nullable)
   - `was_correct INTEGER` (nullable, 0 or 1)
   - `created_at TEXT NOT NULL`
   - WHY: matches PRD data model exactly, dual FK allows scan and recommendation predictions
3. Add UNIQUE constraints:
   - `UNIQUE(recommendation_id, source)` — one prediction per desk per recommendation
   - `UNIQUE(scan_run_id, ticker, source)` — one prediction per ticker per scan per source
   - WHY: idempotent recording, prevents duplicate predictions
4. Add 5 indexes with `CREATE INDEX IF NOT EXISTS`:
   - `idx_predictions_source ON predictions(source)`
   - `idx_predictions_was_correct ON predictions(was_correct) WHERE was_correct IS NOT NULL`
   - `idx_predictions_rec_id ON predictions(recommendation_id) WHERE recommendation_id IS NOT NULL`
   - `idx_predictions_scan_id ON predictions(scan_run_id) WHERE scan_run_id IS NOT NULL`
   - `idx_predictions_ticker ON predictions(ticker)`
   - WHY: performance for attribution queries (by source, by scored status, by FK, by ticker)
