# Task: Data layer — save prediction methods

## Description

Add `save_prediction()` and `save_predictions_batch()` methods to `LearningMixin` in
`data/_learning.py`. These methods INSERT prediction records into the `predictions` table,
following existing mixin patterns (parameterized queries, Row factory, `commit` parameter).

## Acceptance Criteria

- [ ] `save_prediction(prediction: Prediction, *, commit: bool = True) -> int` method added
- [ ] `save_predictions_batch(predictions: list[Prediction], *, commit: bool = True) -> list[int]` method added
- [ ] Parameterized INSERT queries (no string interpolation)
- [ ] Returns auto-generated `id` from database
- [ ] UNIQUE constraint violation raises `aiosqlite.IntegrityError` (not silenced)
- [ ] Empty batch returns empty list (no error)
- [ ] Unit tests pass

## Technical Details

- Follow `save_strategy_rule()` pattern from `_learning.py`
- INSERT all 12 non-id fields (recommendation_id through created_at)
- Use `cursor.lastrowid` for single insert, `executemany` or loop for batch
- `created_at` serialized as ISO string: `prediction.created_at.isoformat()`
- `was_correct` serialized as INTEGER: `None`, `0`, or `1` (match SQLite convention)
- `predicted_direction` stored as `.value` string
- `source` stored as `.value` string

   ```python

       self, prediction: Prediction, *, commit: bool = True,
   ) -> int:
   ```
   - WHY: single-prediction INSERT for scan pipeline (one prediction per ticker)
2. Build parameterized INSERT with 12 columns, using `?` placeholders:
   - Map `prediction.source.value`, `prediction.predicted_direction.value`, `prediction.created_at.isoformat()`
   - Map `prediction.was_correct` to `int(v)` if not None, else None
   - WHY: follows existing `save_strategy_rule()` pattern, prevents SQL injection
3. Use `cursor.lastrowid` to return the auto-generated id
   - WHY: callers need the id for linking predictions to other records
4. Add `save_predictions_batch()` method using a loop over `save_prediction()` with `commit=False`, then single commit at end:
   - WHY: batch INSERT for orchestrator (8+ predictions per recommendation), single transaction for atomicity

   - WHY: type annotations for method signatures
