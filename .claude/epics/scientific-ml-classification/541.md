# Task: ML Regime Inference in Pipeline

## Description
Add `classify_regime_ml()` to `indicators/regime_ml.py` — loads a pre-trained GBM model from `data/model_cache/regime_classifier.pkl` and classifies the current market regime from the indicator feature vector. Returns class probabilities as a NamedTuple. Config-gated via `MLConfig.enable_ml_regime: bool = False`. Wire into scan pipeline Phase 2 via `phase_scoring.py`.

## Acceptance Criteria
- [ ] `classify_regime_ml()` function in `indicators/regime_ml.py` loads model from configurable path
- [ ] Returns `RegimeClassification` NamedTuple with `predicted_regime: str`, `probabilities: dict[str, float]`, `confidence: float`
- [ ] Returns `None` when model file not found, scikit-learn not installed, or feature extraction fails
- [ ] Guarded scikit-learn + joblib import (same pattern as `_get_markov_regression()`)
- [ ] Config flag `enable_ml_regime: bool = False` added to `MLConfig`
- [ ] `IndicatorSignals` gets new field `ml_regime_confidence: float | None = None`
- [ ] `MarketContext` gets new field `ml_regime: str | None = None` and `ml_regime_confidence: float | None = None`
- [ ] Pipeline Phase 2 calls `classify_regime_ml()` when config flag enabled

## Technical Details
- Extends existing `indicators/regime_ml.py` (currently has Markov-switching only)
- `RegimeClassification` is a `NamedTuple` (indicator module convention: no Pydantic models)
- Feature extraction reuses the same `FEATURE_NAMES` and logic from Task 001's training script
- Model loading should be cached (load once, reuse) — module-level `_cached_model` variable with `_load_model()` helper
- `confidence` = max probability across classes (the winning class probability)
- Pipeline integration: `scan/phase_scoring.py` calls `classify_regime_ml(signals)` after standard indicators, populates `IndicatorSignals.ml_regime_confidence`
- Agent context: `agents/_parsing.py` renders `ml_regime` + `ml_regime_confidence` in appropriate context block
