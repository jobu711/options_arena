# Task: Write recommendation regression tests

## Description

Write comprehensive regression tests for the recommendation system BEFORE deleting old debate files (task 007). This ensures the new system is fully verified before removing the old one. Tests cover: API endpoint behavior, CLI rendering, backward-compat old debate retrieval, batch mode, fallback path, and end-to-end recommendation flow. This is the "never leave a gap" test-first strategy from the epic's architecture decisions.

## Acceptance Criteria

- [ ] API regression tests: single recommendation, batch, backward-compat GET, 404 handling
- [ ] CLI regression tests: single ticker, batch, export, fallback-only, provider flag
- [ ] E2E test: full recommendation flow with TestModel (no real API calls)
- [ ] Backward-compat test: old debate IDs still resolve via GET endpoint
- [ ] All tests pass with recommendation system active
- [ ] Test count: minimum 20 new test cases across 3 files
- [ ] All tests use `pydantic_ai.models.test.TestModel` (never real LLM calls)

## Technical Details

- Tests must use `ALLOW_MODEL_REQUESTS = False` at module level (agents test convention)
- Factory functions needed for `RecommendationResult`, `PositionRecommendation`, domain assessments
- API tests use `httpx.AsyncClient` with FastAPI `TestClient`
- CLI tests use Typer `CliRunner`
- E2E test mocks services but runs full pipeline through `run_recommendation()`
- Backward-compat tests seed `ai_theses` table with old debate data, verify GET returns it
