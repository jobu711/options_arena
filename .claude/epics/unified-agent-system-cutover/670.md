# Task: Rewrite API debate routes and schemas for run_recommendation()

## Description

Rewrite the API debate routes (`api/routes/debate.py`) to use `run_recommendation()` instead of `run_debate()`. Add recommendation response schemas to `api/schemas.py`. The backward-compat `GET /api/debate/{id}` endpoint must check both `recommendation_results` (new) and `ai_theses` (old) tables. WebSocket progress events adapted for parallel desk execution + synthesis.

## Acceptance Criteria

- [ ] `POST /api/debate` starts `run_recommendation()` as background task
- [ ] `POST /api/debate/batch` iterates with `run_recommendation()` per ticker
- [ ] `GET /api/debate/{id}` checks `recommendation_results` first, falls back to `ai_theses`
- [ ] New `RecommendationResponse` schema added to `schemas.py`
- [ ] WebSocket events adapted: desk progress (parallel) + synthesis step
- [ ] Background task persists `RecommendationResult` via `RecommendationMixin`
- [ ] Operation mutex preserved (one scan/debate at a time)
- [ ] Old debate data still viewable via `GET /api/debate/{old_id}`

## Technical Details

### Route Changes (`api/routes/debate.py`)

**`_run_debate_background()` → `_run_recommendation_background()`**:
- Replace `run_debate()` call with `run_recommendation()`
- `run_recommendation()` returns `RecommendationResult` (not `DebateResult`)
- Persist via `repo.save_recommendation_result()` (from `RecommendationMixin`, added in orchestrator epic)
- Agent prediction extraction: `RecommendationResult` has `assessments` list — extract predictions differently

**`start_debate()` POST handler**:
- Same request validation, operation mutex, background task launch
- Pass new config fields: `synthesis_timeout`, `desk_parallelism`, `disabled_desks`
- `DebateRequest` schema: remove `enable_rebuttal`/`enable_volatility_agent` fields

**`start_batch_debate()` POST handler**:
- Same pattern — iterate with `run_recommendation()` per ticker
- Progress events: per-ticker + per-desk within ticker

**`get_debate()` GET handler**:
- First: try `repo.get_recommendation_result(debate_id)` — returns `RecommendationResult | None`
- If None: try existing `repo.get_debate(debate_id)` — returns old debate data
- Return appropriate schema per table hit
- 404 if both miss

### Schema Changes (`api/schemas.py`)

- Remove `enable_rebuttal` and `enable_volatility_agent` from `DebateRequest`
- Add `RecommendationResponse` — serializes `RecommendationResult` for API
- Add `AssessmentSummary` — lightweight assessment rendering per desk
- Add `PositionRecommendationResponse` — contract, entry/exit, sizing
- Keep `DebateResultDetail` for backward-compat old data rendering

### WebSocket Changes

- Desk progress: emit `{"phase": "desk", "desk": "trend", "status": "running"}` for each desk
- Synthesis progress: emit `{"phase": "synthesis", "status": "running"}`
- Keep existing WebSocket bridge pattern (`WebSocketProgressBridge` + `asyncio.Queue`)
