# Task: Integration tests — orchestrator + persistence round-trip

## Description
Write integration tests that exercise the full `run_recommendation()` pipeline end-to-end
using `TestModel`, `:memory:` SQLite, and mock services. Verify persistence round-trip:
save → query → validate all fields. Also verify the old `orchestrator.py` (`run_debate`)
still works with import-forwarded functions from `_context.py`.

## Acceptance Criteria
- [ ] Integration test file with 6+ test cases exercising full pipeline
- [ ] Persistence round-trip verified (save → get by ID → fields match)
- [ ] `recommendation_protocol` column correctly tagged as `'recommend_v1'`
- [ ] Old `run_debate()` still works (backward compat regression test)
- [ ] All tests use `:memory:` SQLite and `TestModel` — no real API calls

## Technical Details

### Test Strategy
These tests differ from Task 004's unit tests by:
1. Using real `Repository` with `:memory:` SQLite (not mocked)
2. Exercising the full pipeline including persistence
3. Verifying DB rows match the returned `RecommendationResult`
4. Using real `Database` + `Repository` fixtures (migrations run)

### Key Assertions
- `RecommendationResult` fields match corresponding DB columns in `recommendation_results`
- `AgentPrediction` rows created with `recommendation_protocol='recommend_v1'`
- Decimal precision preserved through save → read cycle
- `assessments_json` deserializes back to correct `AnyAssessment` types
- `is_fallback` flag correctly reflects pipeline state

### Backward Compatibility Test
- Import `run_debate`, `build_market_context`, `extract_agent_predictions` from `orchestrator.py`
- Run `run_debate()` with `TestModel` — verify it still produces `DebateResult`
- This confirms import-forwarding from `_context.py` works correctly
