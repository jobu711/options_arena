## Description
Bump version to 2.10.0 across all 6 locations identified in research, wire `api/app.py` to use `importlib.metadata` for dynamic versioning, and generate `CHANGELOG.md` from git history grouped by epic/phase.

## Acceptance Criteria
- [ ] `pyproject.toml` version = `"2.10.0"`
- [ ] `web/package.json` version = `"2.10.0"`

- [ ] `.claude/context/progress.md` version = `2.10.0`
- [ ] `src/options_arena/api/app.py` version sourced from `importlib.metadata` (not hardcoded)
- [ ] `CHANGELOG.md` generated with release history grouped by epic
- [ ] `docs/technical-reference.md` updated (via `python tools/docgen.py`)

## Technical Details
- Research identified 6 version locations (see research.md "Version Locations" table)
- `api/app.py` currently hardcodes `version="1.5.0"` — completely out of sync
- `src/options_arena/__init__.py` already reads version from `importlib.metadata` — use same pattern in `api/app.py`
- `docs/technical-reference.md` auto-updates when `python tools/docgen.py` runs (reads version from pyproject.toml)
- CHANGELOG should group commits by epic/phase using conventional commit prefixes
- Git history spans ~35 epics — manual grouping from `git log --oneline` output

## Execution

### Read First
Files that MUST be read before starting this task:
- `pyproject.toml` — current version field location
- `src/options_arena/__init__.py` — existing `importlib.metadata` pattern to reuse
- `src/options_arena/api/app.py` — find hardcoded `version="1.5.0"` in FastAPI constructor
- `web/package.json` — current version field

### Action
1. In `pyproject.toml`, change `version = "2.8.0"` to `version = "2.10.0"`
   - WHY: Primary version source — all other locations derive from or mirror this
2. In `web/package.json`, change `"version": "2.8.0"` to `"version": "2.10.0"`
   - WHY: Frontend version must match backend
3. Run `cd web && npm install && cd ..` to update `package-lock.json`
   - WHY: Lock file must reflect package.json version change
4. In `src/options_arena/api/app.py`, replace hardcoded `version="1.5.0"` with dynamic version:
   ```python
   from importlib.metadata import version as pkg_version
   # In create_app():
   app = FastAPI(title="Options Arena", version=pkg_version("options-arena"))
   ```
   - WHY: Ensures API version always matches pyproject.toml — eliminates future drift
5. In `.claude/context/progress.md`, update version reference to `2.10.0`
   - WHY: Context file must reflect release version
6. Generate CHANGELOG.md from git history:
   - Run `git log --oneline --format="%h %s" | head -500` to get commit history
   - Group by epic/phase, organize by conventional commit prefix (feat, fix, refactor, etc.)
   - Include: version header, date, grouped changes, notable additions
   - WHY: PRD requires CHANGELOG.md for release
7. Run `python tools/docgen.py` to regenerate `docs/technical-reference.md`
   - WHY: Picks up new version from pyproject.toml
8. Commit: `chore: bump version to 2.10.0 and generate CHANGELOG`
   - WHY: Version changes are a single atomic commit
