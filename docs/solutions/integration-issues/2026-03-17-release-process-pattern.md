## Problem

Options Arena had completed 35 epics with 800+ commits but had never cut a formal
release. Version numbers were inconsistent (`pyproject.toml` said 2.8.0, `api/app.py`
said 1.5.0), no git tags existed, no CHANGELOG existed, and the codebase had never been
comprehensively audited.

## Root Cause

Feature development was prioritized over release hygiene. Each epic was merged to master
without version bumping or release artifacts.

## Solution

Three-phase release hardening process:

### Phase 1: Cleanup & Audit
1. Clean stale artifacts (worktrees, archived epics, progress.md)
2. Run `/full-audit` (7 agents in parallel) + `/math-audit` simultaneously
3. Triage findings into P1 (must-fix) vs P2-P4 (document)
4. Fix all P1 findings, verify with lint + type check + critical tests

### Phase 2: Verification
1. Full test suite (`pytest tests/ -n auto`) — verify 100% pass rate
2. Migration integrity — fresh DB from all 33 migrations
3. Optional extras (`[ml]`) — install and run relevant tests
4. Performance baseline — timing for scan, debate, batch (informational)

### Phase 3: Release Cut
1. Bump version in all 6 locations:
   - `pyproject.toml` (primary source)
   - `web/package.json` + `package-lock.json`
   - `.claude/context/progress.md`
   - `api/app.py` → wire to `importlib.metadata` (permanent fix)
   - `docs/technical-reference.md` → regenerated by `docgen.py`
2. Generate `CHANGELOG.md` from git history grouped by epic
3. Document P2-P4 in `docs/known-limitations-{version}.md`
4. Final commit + git tag

### Version Locations Checklist

| File | How to update |
|------|--------------|
| `pyproject.toml` | Manual edit (primary source of truth) |
| `web/package.json` | Manual edit |
| `web/package-lock.json` | `npm install --package-lock-only` |
| `progress.md` | Manual edit |
| `api/app.py` | Now dynamic via `importlib.metadata` — no manual edit needed |
| `docs/technical-reference.md` | `python tools/docgen.py` — reads from pyproject.toml |

## Prevention Rule

1. **Wire api/app.py to importlib.metadata** — done, never hardcode version again
2. **Run `/release-prep`** or follow the Phase 1-2-3 process before tagging
3. **Always bump all 6 locations** — use the checklist above
4. **Tag after clean git status** — `git tag vX.Y.Z` only on a clean working tree
5. **Generate CHANGELOG before tagging** — tag should include the CHANGELOG
